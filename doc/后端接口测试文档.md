# CDP ABM 360 — 后端接口 pytest 测试文档

> 文档生成日期：2026-07-12
> 测试框架：`pytest` + `FastAPI TestClient`
> 测试代码位置：`ruijie-cdp/backend/test/pytest/`
> 当前状态：**88 个用例全部通过**，零外部依赖（无需真实 MySQL / Elasticsearch / DeepSeek）。

---

## 1. 设计目标与原则

本套件面向 `backend/app/routers/*` 中的全部后端接口，按工程化标准实现，遵循以下原则：

1. **默认 mock 模式，零外部依赖**
   通过 `app.dependency_overrides` 将依赖注入的 `get_db` 替换为内存版 `MockDBSession`
   （见 `conftest.py`）。它记录所有执行过的 SQL 与绑定参数，并可按 SQL 子串返回预设结果。
   因此测试既能断言 **HTTP 响应结构**，也能断言后端 **实际生成的 SQL**。

2. **不经由 `get_db` 的路由用 `monkeypatch` 隔离**
   `sync`（ETL 引擎）、`es`（ES 客户端）、`ai`（LLM 服务）、`pool`（连接池）等不通过
   `get_db` 获取会话，测试内使用 `monkeypatch` 替换底层引擎 / 客户端 / 服务函数，杜绝真实副作用。

3. **可读可维护**
   每个路由对应一个 `test_*.py`；服务层的 SQL 生成逻辑单独测试；命名清晰、断言明确。

4. **回归守护**
   将历史 bug 固化为回归用例，防止再次引入（见第 6 节）。

## 4. 测试基础设施（`conftest.py`）

### 4.1 `Row`
轻量结果行，兼容 SQLAlchemy `Row` 的位置访问、键访问、属性访问以及 `dict()` 转换。
支持 `missing_none` 模式：用于聚合查询（`one()`）无数据时，访问不存在的键 / 属性返回 `None`
而非抛错。

### 4.2 `MockResult`
兼容 SQLAlchemy `Result` 的常用方法：`mappings()` / `all()` / `fetchall()` /
`fetchone()` / `first()` / `one()` / `scalar()` / `rowcount`。

### 4.3 `MockDBSession`
模拟 `Session`：

- `add_result(match_substr, *, rows=, scalar=, rowcount=)`：注册“当执行的 SQL 包含
  `match_substr` 时返回该结果”。**按注册顺序返回第一个命中项**，故更精确的匹配应先注册。
- `execute(statement, params)`：记录 `(sql, params)` 到 `calls`，返回命中的 `MockResult`，
  未命中时返回空结果集（`MockResult([], scalar=0, rowcount=0)`）。
- `commit()` / `rollback()` / `close()`：记录状态，无副作用。

### 4.4 Fixtures
- `mock_db`：返回干净的 `MockDBSession`，可在用例内 `add_result` 预设数据。
- `client`：`TestClient`，并把 `get_db` 依赖覆盖为同一个 `mock_db` 实例，用例结束自动清理。

## 5. 运行方式

在 `ruijie-cdp/backend/` 目录下执行：

```bash
# 1. 安装测试依赖（同时确保已安装后端运行依赖 requirements.txt）
pip install -r test/pytest/requirements-test.txt

# 2. 运行全部测试
python -m pytest test/pytest -q

# 3. 运行指定文件 / 用例
python -m pytest test/pytest/test_customer_detail.py -v
python -m pytest test/pytest/test_etl_logic.py -v

# 4. 显示 print 输出与最慢的 10 个用例
python -m pytest test/pytest -v -s --durations=10

# 5. 只跑上次失败的用例
python -m pytest test/pytest --lf
```

预期输出（示例）：

```
88 passed, 1 warning in ~1s
```

> 说明：
> - 测试默认使用 mock，不会连接 `backend/.env` 中的数据库。
> - 唯一的 warning 来自 `starlette.testclient` 对 `httpx` 的弃用提示，不影响结果。
> - Windows 环境下，若用 PowerShell 重定向输出请使用 `Tee-Object`，避免 `&` 语法报错。

## 6. 回归守护用例

以下用例将历史生产 bug 固化，防止回归：

### 6.1 ETL 临时表名修复（`test_etl_logic.py`）
历史 bug：`dws_contact_mapping` 载入查询引用了不存在的临时表 `tmp_icp_companies`，
导致 `(1146, "Table '...tmp_icp_companies' doesn't exist")`。
修复后应引用 `tmp_icp_customers`。用例断言 `etl_sync.py` 中相关查询只引用
`tmp_icp_customers`，不再出现 `tmp_icp_companies`。

### 6.2 去重证据评分 IN 替代 LIKE（`test_company_dedup.py`）
历史 bug：`batch_calculate_evidence_scores` 对每个公司名生成一条 `related_company LIKE :name_N`
并用 `OR` 串联，公司数上千时产生巨型 SQL（`... LIKE %(name_1366)s OR ...`）。
修复后改为精确 `IN (...)` 匹配。用例断言：针对 ODS 表的查询包含 `IN (`、不包含 `LIKE`；
且无共享联系人时每个候选对的证据分为 `(0.0, 0, [])`。

## 7. 编写新测试的约定

1. **优先 HTTP 层测试**：通过 `client.get/post(...)` 验证状态码与响应信封结构，最贴近真实调用。
2. **需要断言 SQL 时**：可直接调用 router / service 函数并检查 `mock_db.calls`。
   - 注意：直接调用带 `Query(...)` 默认值的 router 函数时，FastAPI **不会**解析默认值，
     必须显式传入全部参数（参见 `test_customer_list.py` 中的 `_call` 包装器）。
3. **预设数据用 `mock_db.add_result`**：更精确的 SQL 子串先注册。
4. **隔离外部依赖用 `monkeypatch`**：patch 目标应指向 **实际引用该符号的模块**
   （例如 `reset_pool` 在 `app.routers.pool` 中以名字导入，应 patch `app.routers.pool.reset_pool`）。
5. **中文注释**、4 空格缩进、每行 ≤ 100 字符，与项目编码规范保持一致。

## 8. 后续可扩展方向

- **覆盖率统计**：`pip install pytest-cov`，运行 `python -m pytest test/pytest --cov=app --cov-report=term-missing`。
- **CI 集成**：在流水线中执行 `python -m pytest test/pytest -q`，作为合并前门禁。
- **集成测试（可选）**：如需连真实测试库，可新增独立标记（`@pytest.mark.integration`）
  并通过环境变量开关，默认不随单元测试运行。
