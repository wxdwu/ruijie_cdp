# 二、落地方案

- 目前计划让业务方给出之前提到的2300个彩光ICT客户名单，数仓将客户所关联的CRM数据、三张表的用户行为数据取出来（或者数仓提供查询接口，IT侧查询数据并每日更新查询增量数据）推送至IT侧数据库，IT侧负责数据合并、应用搭建、AI落地

- 应用仅保留360客户列表页、客户详情页、AI对话、AI审核页面

- AI对话窗口仅保留基础的对话、NL2SQL、数据导出能力

- 功能优先级如下：

    - P0：360客户列表页、客户详情页（概览、联系人两个TAB）、AI对话（NL2SQL、数据导出）

    - P1：专项看板页、客户详情页（其他TAB）、AI审核页面

    - P2：AI对话（其他几个TAB）、管理驾驶舱、OA登陆

1\.业务侧

请业务方确认2300个客户名单列表及目前DEMO方案是否可行

2\.数仓侧

请数仓协同AI团队确认取数方式

注意：需要做NER，提取客户名称中关键实体，然后通过全名、简称、提取实体来做数据查询、推送

3\.AI团队

协同业务确认方案，如有疑问进行调整

协同数仓进行取数

DEMO产品搭建，包括数据清洗去重匹配、报表建设、AI落地（AI单客户/联系人洞察、AI对话）

**配图：数据清洗链路字段口径标注**

### 10\.1 清洗目标

目标结构：唯一公司名称 → 若干联系人 → 联系人下的互动行为 → CRM 中相关商机。清洗后每个页面只消费统一公司、统一联系人、统一互动和 CRM 商机四类对象。

### 10\.2 公司名称聚合策略

|步骤|输入|处理|输出 / 阈值|
|---|---|---|---|
|候选抽取|CRM 客户名、线索业务机会客户名 / 最终公司名称 / 客户单位、内容公司、会话客户\-公司名称 / 单位名称 / 客户名称|NER 提取公司实体，清理括号、全半角、空格、特殊符号、常见后缀|company\_candidate|
|规则相似度|标准化公司名、简称、地区、行业|编辑距离、包含关系、后缀去除、简称映射|rule\_score|
|证据增强|联系人手机号 / 邮箱、行业、省份、来源表、最近更新时间|同手机号 / 邮箱提高置信；行业 / 省份一致小幅加分；仅姓名一致不强合并|evidence\_score|
|大模型校验|候选公司 A/B、别名、联系人证据、来源字段|判断是否同一主体，输出置信和解释|llm\_score|
|综合分|rule\_score、evidence\_score、llm\_score|加权形成 match\_score|\>0\.85 自动合并；0\.6\<score≤0\.85 进公司名称审核；≤0\.6 不聚合|
|合并落库|自动合并或人工确认|聚合至最新一条公司数据，保留 aliases 和 source\_lineage|unified\_company|

“最新一条公司数据”优先级：最近业务时间最大；同日按 CRM \> 线索 \> 会话 / 座席机器人 \> 内容触达 \> linkflow \> 邮件点击；不覆盖证据链，只更新主展示字段。

### 10\.3 联系人对公司聚合的影响

|情况|策略|
|---|---|
|同手机号 / 同邮箱出现在两个相似公司下|作为强证据提高公司 match\_score，但仍需遵守阈值|
|同姓名但手机号 / 邮箱缺失|弱证据，只能进入人工审核或保持独立，不能自动合并公司|
|一个联系人对应多个公司且公司相似度 ≤0\.6|联系人进入人工审核确认队列；公司不合并|
|一个联系人对应多个公司且公司相似度 \>0\.85|公司自动合并，联系人归属合并后公司|
|一个联系人对应多个公司且 0\.6\<相似度≤0\.85|公司和联系人均进入人工审核，审核结果回传|

### 10\.4 互动与商机关联

|对象|关联规则|异常处理|
|---|---|---|
|互动 → 联系人|手机号 / 邮箱优先，其次 contact\_id / anonymous\_id，其次姓名|无联系人标识但有公司名，互动可直接挂公司并标记低置信|
|联系人 → 公司|contact\_company\_binding；默认来自公司清洗结果|多公司冲突进联系人审核|
|商机 → 公司|CRM 客户名匹配统一公司；线索 CRM编号 辅助关联业务机会编码|客户名中置信进公司审核；编码为空不计商机|
|内容 → 客户|内容行为关联联系人或公司；再回挂 account\_id|无法回挂只参与内容匿名统计，不进入客户列表|
