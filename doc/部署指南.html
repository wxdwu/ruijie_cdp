2 环境前置条件

2.1 软件要求

  • Docker ≥ 20.10（已检测到：v27.1.1 ✅）
  • Docker Compose v2（已检测到：v2.29.1 ✅）
  • MySQL 客户端（用于执行初始化 SQL 脚本，可选）

2.2 网络要求

  • 部署服务器需能访问 MySQL 数据库 192.168.159.22:33307
  • 部署服务器需能访问外网 https://api.deepseek.com（LLM 对话）
  • （可选）需能访问 https://api.openai.com/v1（Embedding 向量）
  • 宿主机端口 28080 需可用（或自定义端口）

2.3 数据库账户

需要一个拥有 app_cdp 数据库读写权限的 MySQL 账户。当前默认配置：

主机192.168.159.22
端口33307
用户名app_cdp
密码******（通过环境变量传入）
数据库名app_cdp

3 数据库准备

3.1 DWS 聚合表初始化

项目依赖一组 DWS（数据仓库服务层）聚合表，需在部署前执行 SQL 脚本创建：

# 连接到 MySQL 数据库
mysql -h 192.168.159.22 -P 33307 -u app_cdp -p app_cdp

# 在 MySQL 命令行中依次执行：
# 1. 创建 DWS 聚合层表（核心表）
source scripts/build_aggregation.sql;

# 2. 创建同步日志表
source scripts/create_sync_log_table.sql;

# 3. 创建重要客户表（ODS 层）
source scripts/create_key_customer_table.sql;

# 4. 补充字段和注释（按需执行）
source scripts/add_attribute_field.sql;
source scripts/add_sync_batch_fields.sql;
source scripts/add_comments.sql;
source scripts/add_comment_to_dws_cust360.sql;
source scripts/addComment_key_customer_table.sql;
📋 创建的 DWS 表清单 dws_sync_meta · dws_contact_mapping · dws_customer_360 · dws_contact_360 · dws_interaction_detail · dws_review_queue · dws_sync_log · ods_key_customer

5 Docker Compose 部署

5.1 一键启动

# 进入项目根目录
cd /path/to/ruijie-cdp

# 构建镜像并后台启动（首次会拉取基础镜像，耗时较长）
docker compose up -d --build

该命令会：

  1. 构建 backend 镜像：基于 python:3.13-slim，安装 Python 依赖，复制应用代码
  2. 构建 nginx 镜像：多阶段构建——先用 node:22-alpine 编译前端，再用 nginx:1.27-alpine 托管
  3. 创建 ruijie_cdp 桥接网络
  4. 启动两个容器并建立网络互联

5.2 查看启动状态

# 查看容器状态
docker compose ps

# 查看后端日志（实时跟踪）
docker compose logs -f backend

# 查看 Nginx 日志
docker compose logs -f nginx

5.3 首次数据同步

容器启动后，ETL 调度器会自动每小时运行一次。如需立即触发首次全量同步：

# 手动触发 ETL 全量同步
curl -X POST http://localhost:28080/api/admin/etl/run

5.4 停止与重启

# 停止所有服务
docker compose down

# 停止并删除镜像（完全清理）
docker compose down --rmi local

# 重新构建并启动（代码更新后）
docker compose up -d --build

7 运维与监控

7.1 ETL 定时调度

后端内置 APScheduler，每小时自动执行一次 ETL 增量同步（ODS → DWS）。

  • 调度任务 ID：etl_hourly
  • 策略：合并错过的执行（coalesce）、单实例运行（不重叠）
  • 容错：5 分钟 misfire 宽限期

7.2 可选：Crontab 外部定时同步

项目提供了 scripts/incremental_sync.sh 脚本，可通过 crontab 部署为外部定时任务（与内置调度二选一或互补）：

# 编辑 crontab
crontab -e

# 每小时第 30 分钟执行增量同步
30 * * * * /path/to/ruijie-cdp/scripts/incremental_sync.sh

# 注意：需修改脚本中的 API_BASE_URL 指向实际地址
# API_BASE_URL="http://127.0.0.1:28080"

7.3 日志管理

# 查看最近 100 行后端日志
docker compose logs --tail 100 backend

# 查看最近 5 分钟的所有日志
docker compose logs --since 5m

# 导出日志到文件
docker compose logs backend > backend_$(date +%Y%m%d).log 2>&1

7.4 更新部署

# 拉取最新代码后重新构建
git pull
docker compose up -d --build

# 仅重启后端（不重新构建）
docker compose restart backend

8 常见问题排查

Q1: 后端启动报 DB_PASSWORD is required

原因：.env 文件未创建或 DB_PASSWORD 未设置。这是唯一一个必填环境变量。

# 在项目根目录创建 .env 并设置密码
echo 'DB_PASSWORD=你的密码' > .env

Q2: 后端健康检查一直 unhealthy

  1. 检查数据库连接：docker compose logs backend | grep -i "sql\|connect\|error"
  2. 确认 MySQL 可达：telnet 192.168.159.22 33307
  3. 确认 DWS 表已创建（执行了 SQL 脚本）

Q3: 前端页面空白或 502

  1. 检查 Nginx 容器是否正常：docker compose ps
  2. 检查后端是否已启动：docker compose logs backend
  3. Nginx 依赖 backend 启动后才可正常代理

Q4: AI 对话功能无响应

  1. 检查 LLM_API_KEY 是否正确配置
  2. 确认服务器可访问 https://api.deepseek.com
  3. 查看后端日志：docker compose logs backend | grep -i "llm\|openai\|deepseek"

Q5: ETL 同步无数据

  1. 确认 ODS 源表存在且有数据：SELECT COUNT(*) FROM ods_crm_contact_day;
  2. 手动触发同步并查看返回：curl -X POST http://localhost:28080/api/admin/etl/run
  3. 检查同步日志表：SELECT * FROM dws_sync_log ORDER BY id DESC LIMIT 5;

Q6: 端口 28080 被占用

# 在 .env 中修改端口
echo 'NGINX_PORT=28081' >> .env
docker compose up -d
